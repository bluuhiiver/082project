# Skinly — 화해(Hwahae) 스타일 로컬 성분 분석 앱 계획

## 1. 화해(Hwahae)가 어떻게 작동하는가

화해(Hwahae, "화장품을 해석하다")는 한국의 대표적인 화장품 정보/리뷰 앱으로, 핵심 동작 방식은 다음과 같다.

- **성분 분석(성분 사전)**: 제품의 전성분을 등록된 성분 데이터베이스와 대조해 유해/논란 성분(알레르기 유발물질, 자극 성분, 여드름 유발 성분 등)과 유익 성분을 자동으로 식별해 보여준다.
- **피부타입 개인화**: 가입 시 피부타입(지성/건성/복합성/민감성/정상)과 피부 고민(여드름, 건조함, 노화, 색소침착, 홍조 등)을 입력받아, 이후 모든 분석 결과를 그 프로필에 맞춰 개인화한다.
- **제품 검색 및 랭킹**: 제품명/브랜드로 검색하고, 카테고리별 인기 순위, 리뷰, 평점을 제공한다.
- **바코드 스캔**: 매장에서 실물 제품의 바코드를 스캔해 즉시 성분 분석 결과를 확인할 수 있다.
- **찜(즐겨찾기)/최근 본 제품**: 관심 제품을 저장하고 조회 이력을 관리한다.
- **제품 비교**: 두 제품의 성분·평점을 나란히 비교해 우열을 보여준다.
- **구매 연결**: 올리브영, 각종 이커머스로 연결되는 구매 링크를 제공한다.
- **리뷰/커뮤니티**: 실사용자 리뷰, 피부타입별 평점 분포 등 소셜 증빙 제공 (본 로컬 버전에서는 서버·계정 인프라가 필요해 범위에서 제외).

## 2. 로컬 앱으로 재구축 시 제약과 설계 결정

- 화해의 자체 제품/성분 DB와 API는 비공개이므로, 재구축판은 **오픈소스 무료 API인 Open Beauty Facts**를 제품 검색/바코드 조회 백엔드로 사용한다 (회원가입/키 불필요, CORS 허용).
- 계정 시스템 없이 **기기 로컬(localStorage)에만 프로필/찜/이력을 저장**해 "내 기기의 로컬 앱"이라는 요구에 맞춘다. 서버, DB, 로그인 없이 정적 파일(HTML/CSS/JS)만으로 동작 + PWA로 설치 가능.
- 성분 분석 로직은 화해와 동일한 원리(피부타입/고민 기반으로 문제 성분·유익 성분 태깅 후 점수화)를 자체 규칙 기반 사전(코메도제닉, 자극성, EU 26대 알레르기 성분, 유익 성분)으로 재구현한다.
- 리뷰/커뮤니티/랭킹처럼 서버·다수 사용자 데이터가 필요한 기능은 로컬 단일 사용자 앱의 범위를 벗어나므로 제외하고, "인기 검색어" 칩으로 대체한다.

## 3. 핵심 기능 범위 (구현 대상)

| # | 기능 | 상태 |
|---|------|------|
| 1 | 온보딩: 피부타입 + 피부 고민 선택 → 로컬 프로필 저장 | ✅ 구현됨 |
| 2 | 제품 검색 (이름/브랜드, Open Beauty Facts API) | ✅ 구현됨 |

## 4. 개발/검증 계획

1. 로컬 정적 서버로 앱을 구동한다.
2. 브라우저(Playwright)로 온보딩 → 검색 → 상세 조회 → 찜 → 비교 → 바코드(수동 입력 경로)까지 전체 플로우를 실제로 조작해 검증한다.
3. 발견된 버그를 수정하고, 콘솔 에러가 없는지 확인한다.
4. 기본 기능이 처음부터 끝까지(온보딩 → 분석 → 저장) 동작함을 확인하면 커밋/푸시한다.

## 5. 개선 패스 (2차) — 수행 내역

재검증 후 다음을 개선하고 30개 자동 검증 항목(온보딩·분석 엔진 단위 검증·검색·상세·리뷰·찜·비교·새로고침 유지·바코드)을 모두 통과시켰다.

- **버그 수정**
  - GitHub Pages처럼 하위 경로에 배포하면 서비스워커가 절대 경로(`/`) 캐시에 실패해 설치가 깨지던 문제 → 상대 경로(`./`)로 수정, manifest `start_url`/`scope`도 상대 경로로 변경.
  - 성분 파서가 모든 숫자를 제거해 `benzophenone-3`, `laureth-4` 같은 성분이 매칭되지 않던 문제 → 농도(%)·번호 목록만 제거하도록 수정.
  - `fragrance`/`parfum`, `ceramide`/`ceramide np`처럼 같은 성분의 표기 변형이 중복 집계되어 점수가 이중 감점되던 문제 → 표시명 기준 중복 제거 후 점수 계산.
  - 짧은 성분명이 긴 성분명 일부에 오탐 매칭되는 것 방지(6자 미만은 완전 일치만 허용).
- **화해 스타일 한국어화**: 전체 UI 한국어 전환, 성분마다 한국 화장품 성분명(전성분 표기명) 병기, 주의 카테고리 한국어화(모공 막힘 유발/자극 유발/알레르기 주의), 인기 검색어에 K-뷰티 브랜드 추가, 구매 링크를 쿠팡·네이버쇼핑 중심으로 개편.
- **성분 DB 확장**: 약 80종 → 130여 종 (EU 알레르겐 추가분, 미네랄오일·트리클로산·벤조페논-3 등 논란 성분, 어성초·갈락토미세스·비피다·PDRN·감초 등 K-뷰티 유익 성분).
- **나의 리뷰**: 제품 상세에서 별점(1~5)과 메모를 기록하는 로컬 개인 리뷰 추가 — 화해의 리뷰 기능을 단일 사용자 로컬 앱에 맞게 재해석.

## 6. 개선 패스 (3차) — 로컬 큐레이션 카탈로그

Open Beauty Facts는 한국어 검색이 거의 되지 않고 K-뷰티 커버리지가 약하다. 이를 보완하기 위해:

- **`catalog.js`**: 올리브영/예스스타일 스타일의 실제 인기 제품 148개(87개 브랜드, 토너·세럼·크림·선케어·클렌징·마스크·아이케어·바디·헤어 전 카테고리)를 큐레이션. 각 제품에 한국어 검색 키워드(`kw`)와 대표 성분 요약을 수록(전체 전성분이 아님을 파일 헤더에 고지).
- **병합 검색**: 검색 시 로컬 카탈로그(한국어 매칭·정확도순)를 먼저 보여주고 OBF 원격 결과를 코드 중복 제거 후 이어붙인다. 원격이 실패해도 로컬 결과만으로 동작(오프라인 내성).
- **바코드 로컬 우선**: 카탈로그에 있는 바코드는 API 호출 없이 즉시 조회.
- **둘러보기 탭**: 인기 검색어 대신 카테고리 칩(토너/세럼/크림/선크림/클렌징/마스크팩/아이케어/바디/헤어/미스트) + 인기 브랜드 칩으로 개편.
- 데모(Artifact)는 동일 카탈로그를 인라인해 외부 API 없이 동작. 검증: 데모 16항목 + 실앱 병합/폴백 6항목 자동 테스트 전부 통과.

## 7. 개선 패스 (4차) — 추천 & 랭킹

화해의 핵심 기능 두 가지를 추가.

- **🏆 랭킹 탭**: 카탈로그 148개 제품을 내 피부 프로필 기준 매치 점수로 정렬, 카테고리 칩(전체/토너/세럼·에센스/크림·로션/선케어/클렌징/마스크·팩/아이케어/립케어/바디/헤어/미스트/베이스)으로 필터. 카테고리는 각 제품 kw의 카테고리 단어로 판별.
- **🧬 성분이 비슷한 제품**: 제품 상세에서 성분 지문(성분 텍스트에서 DB 등록 성분 집합 추출, 표기 변형은 한글명으로 통합) 간 자카드 유사도 + 동일 카테고리 보너스로 상위 6개 추천. OBF에서 조회한 제품에도 동작.
- **✨ 내가 쓰는 제품 기반 추천(홈)**: 찜(가중치 2)·별점 4+ 리뷰(2)·최근 본(1) 제품의 성분 지문과의 가중 유사도 합 + 개인화 점수 보정으로 상위 8개를 홈에 추천. 이미 본/찜한 제품은 제외.

검증: 데모 자동 테스트 13항목(랭킹 렌더/카테고리 필터/상세 진입, 유사 제품 렌더/전환, 홈 추천 렌더/제외 로직/진입) 통과, 실앱 하위 경로에서도 확인.
